fid-router

你发出去的 prompt，中转读不到——而且你能亲自验证。

可验证的无日志 LLM 中转。基于 Intel TDX 机密计算，在你发送之前，用硬件远程证明确认我们跑的是公开、可复现、不记录的代码。不是"请相信我们"，而是"你先验证我们"。

01 验证

发送前先核对

SDK 自动取硬件证明，核对代码指纹链到 Intel 根；对不上就拒发。

02 密封

只对被证明的代码可解

prompt 在你设备上就地加密，只有那个被证明的无日志 enclave 能解——云、运维、数据库都读不到。

03 回执

每次调用可审计

返回一张签名回执（含实际用的模型，防偷偷降级），可存档、可第三方核验。

如果你是 · 用户 / 开发者

用得放心，还能自证

✓发送前可验证、不通过即拒发；我们、云厂商、运维都读不到你的 prompt。
✓每次调用有签名回执，能证明"确实用了你要的模型"。
✓接入是 drop-in：把 base_url 换成我们、打开 verify，兼容 OpenAI / Anthropic SDK。
如果你是 · 中转站 / 有用户渠道的应用方

把"可验证"变成你的卖点

A · 用我们当可验证中转（BYOK）
你有用户、不想自建中转基建：把自己的上游 key 密封交给我们（我们看不到），给你的用户发子令牌。你就能对你自己的用户证明"我们读不到你的对话"。
B · 让你现有的中转"被验证"
在你自己的机器上跑我们可复现的镜像、进我们的验证注册表、拿 "Verified by fid-router" 徽章——赢下不敢用普通中转的隐私敏感客户。
✓面向你终端用户的 verify SDK 免费开源。
诚实边界：本保证只覆盖中转这一跳——你的 prompt 会以明文交付你所选的上游厂商（OpenAI/Anthropic 等），之后受该厂商自身的留存/ZDR 条款约束，这部分我们无法用密码学证明。我们不做"端到端私密"或"零知识推理"这类过度承诺。
